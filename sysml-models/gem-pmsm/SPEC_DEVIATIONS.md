No other SysML calculation, numeric motor parameter, reset value, current threshold, source reward, converter clipping equation, reference bound, or integrator selection changed between these two model files. The exact patch is the checkable inventory. The 1-ms variant is an **experimental change to the published simulation**, not a faithful run of GEM's default `tau=1e-4` environment.

The rotor-frame voltage transform now refreshes at 1 ms and stays fixed during that interval; phase-current observations still use the angle at the beginning of their interval. The source current monitor now samples once per 1 ms, so intermediate current excursions can escape its sampled monitor. The stochastic reference generator still makes the same per-step draws and uses the same clipping bounds, but advances once per 1 ms. A 500–1999-step reference segment therefore lasts 0.5–1.999 seconds instead of 0.05–0.1999 seconds. This changes the target trajectory in physical time. These changes must not be described as merely a tenfold runtime optimization or as numerically identical to ten 100-microsecond steps.

The active `pmsm_pipeline.py` selects `gem-pmsm-1ms/model.sysml`, `DT=0.001`, `HORIZON=3000`, and `CONTROL_REPEAT=1`; `pipeline.py` gives PMSM the same default 3000-step horizon. `gem_pmsm_profiles.py` and `gem_pmsm_adapter.py` add exact hash/signature checks for both source and active timing profiles. `source_environment()` retains the 100-microsecond baseline. A former held-action design kept 30,000 underlying plant steps while reducing only policy calls to 3000; `rl/pmsm_held_action.py` and `gem-pmsm/CONTROL_INTERVAL.md` retain that **historical** path, but it is not the active profile.

## Shield and replacement behavior added by this project

The source motor supplies the current-radius limit, plant equations, converter bounds, and sampled current monitor. It does not supply a next-action shield, local Lipschitz certificate, numerical error budget, safety margin, fallback preference, or search budget. These are CLARITY additions in `rl/pmsm_lipschitz_shield.py` and `rl/continuous_box_spec.py`:

1. Clip each proposed phase action to `[-1,1]`. Build interval bounds for speed and dq currents under that candidate's fixed dq voltage over the whole controller interval, with local derivative/Lipschitz bounds and adaptive proof substeps.
2. Form a current magnitude score using the interval endpoint bounds, a discrepancy allowance relative to a staged native SciPy solver result, and optional cushions `epsilon_d` and `epsilon_q`. Accept only if the upward-rounded normalized squared score is at most 1 **and** the actual source monitor says the staged native result is safe. The default physical cushion on both axes is **0 A**. The method's 1e-10 minimum proof substep, six inflation trials, 32 accepted proof substeps, and depth eight are computation budgets, not sourced motor properties.
3. For an unsafe proposal, try a current-holding voltage lifted into three phase commands, constrained optimization near the Gaussian policy mean with weights `1/std²`, and if needed the `{−1,0,1}³` phase grid and a bounded feasibility search. SLSQP's eight outer passes, 60 preference iterations, 40 feasibility iterations, `1e-8` cone slack, and `1e-10` tolerance are project choices. Every candidate is checked again with the full score and source monitor. Search exhaustion is reported as `SHIELD_BLOCKED`, not a proof that no safe action exists.
4. Candidate evaluation runs an isolated copy of the native solver before selection. When accepted, that **same prepared numerical response** is committed once. This differs from ordinary source action execution and from an a-priori hardware safety filter. The numerical discrepancy budget is computed from the ideal-ODE enclosure and that candidate's native endpoint; it is not an independently derived bound on SciPy error or physical hardware error.

The shield's preference search is a candidate generator, not a global optimum proof. The interval score's precise implementation and the staged solver/commit path have runtime tests, but no universal source-to-runtime refinement proof. Published action-projection, sampled-data filter, and validated-ODE works motivating this design are inventoried in `../../../../outputs/PMSM_safe_action_sources/SOURCE_INDEX.txt` and `../../../../outputs/PMSM_local_Lipschitz_shield_design.pdf`; those works supply no GEM-specific gains or limits.

## Training changes from the source task

| Item | Published source behavior | Current CLARITY choice |
|---|---|---|
| Controller | No trained controller specified | 15-input, three-output, width-64 Gaussian GRU actor-critic, PPO, one optimizer update per complete training episode, and project optimizer settings. Gaussian proposals are unsquashed; the action-domain shield/converter clips them. |
| Two training modes | Not specified | `shielded`: safe executed-action reward passes through. `shielded_punishment`: same tracking reward with a nonnegative intervention cost subtracted when a proposal is changed. Both use the same shield. |
| Tracking reward | `-|speed_error_rpm|/8000` on nonviolation | Training-only cost is capped at `-1` beyond 8000 rpm error. Original source reward and physical RPM errors are recorded separately. This cap is an experimental objective change, not a motor speed safety constraint. |
| Intervention cost | None | `0.025*c/(1+c)` subtracted in punishment mode, where `c` is Euclidean distance between proposed and executed normalized phase actions; correction tolerance `1e-6`. A unit correction costs `0.0125`, equal to 100 rpm of uncapped tracking cost. Maximum is `0.025`, equal to 200 rpm. These weights are pilot choices. |
| Actual current violation reward | Source `-10`; source environment terminates | Training objective substitutes a shared discount-calibrated terminal cost `-(1+0.025)/(1-gamma)` (about `-513.01` at 1 ms) so an immediate violation does not improve the shaped objective. Source `-10` is retained separately. Actual executed violation ends training; successful shield replacement continues it. |
| Discount and advantage trace | Source reward gamma `0.9`; no sourced PPO GAE setting | Experimental 0.5-second discount horizon and 0.1-second direct GAE trace: at 1 ms, gamma about `0.998002`, lambda about `0.992032`. One source reward sample per actual 1-ms plant transition; no ten-step reward sum in the active profile. |
| Reference sequence and seeds | GEM's per-step Wiener reference | Same per-step generator math on the changed clock; training compares shared initial weights/reference seeds, then checkpoint reload evaluation and paired accuracy replay. These evaluations are additional pipeline work, not source behavior. |
| Episode length | Source environment has no project 3-second completion | 3000 active-profile control and plant steps. Trial success means reaching that horizon without an executed violation; it does not assert accurate tracking. |

`pmsm_training_setup.py` and `gem-pmsm/TRAINING_STAGES.md` give the exact objective formulas. The latter also records **historical 100-microsecond and held-action** values, including the approximately `-5125.51` terminal cost; that is not the active 1-ms value. `pmsm_training_comparison.py` defaults to 20 training and three evaluation episodes per arm, and its paired accuracy pass replays trained controllers. `pmsm_pipeline.train()` currently requires a positive evaluation count and always evaluates after training. No later request to strip that extra work has been implemented.

## Proof and pipeline additions

The source GEM repository does not define CLARITY SysML-to-SMV translation or a nuXmv proof of its nonlinear continuous motor. `pmsm_proof` adds a source-derived numerical control-flow relation and a **conditional shield-interface** invariant/threshold check. `formal.py` gained optional IC3, induction, and falsification engines for the isolated precompiled slice. `sysml-models/mc-extract.py` refuses to emit a surrogate proof for this native DOPRI/reference model. `pmsm_proof/README.md` describes the relation, checks, source/runtime distinction, and unresolved proof obligations.

The active 1-ms preparation produced `../../../../outputs/pmsm-coarse-1ms/verification.json`: SMV was generated and the conditional shield contract was checked; its `verified` value is **false** and `publication_blocked` is **true**. That conditional result does not prove the native shield implementation, the numerical runtime, the physical motor, a trained policy, or safe continuation. It must not be reported as full safety verification.

The integration added native-runtime dispatch in `rl/env.py` and `sysml-models/runtime_backends.py`, seed handling and structured observations, a source-reward field in `sysml-models/simulator_adapter.py`/`rl/continuous_env.py`, parser support for an input annotated `#Completion`, and new SciPy/pycparser dependencies. The PMSM branch in `pipeline.py` calls formal preparation, then `runtime_preflight()`, and then training in PPO mode. `runtime_preflight()` itself performs three rollouts: 3000 zero-action steps, an unsafe-action detection sequence, and up to 3000 shielded unsafe proposals. These extra rollouts are **project-added runtime checks**, not requirements of GEM or nuXmv. The separate `../../../../work/run_coarse_full_pipeline.py` also inserted this preflight before the two-mode comparison; the last requested run was stopped during that phase, before either active-profile training mode began. The working pipeline code still contains this behavior; this document records it without altering it.

## Second-order checker update, 15 October 2026

Following the source-deviation snapshot above, the user authorized a second-order checker trial and pass-through shielded training/evaluation with nuXmv skipped. `rl/pmsm_lipschitz_shield.py` now constructs smooth-branch endpoints as `X + h*f(X) + h²*J(X)*f(X)/2`, plus a component-wise symmetric third-order remainder bounded over the validated enclosing tube. The third derivative is bounded using `H_f[f,f] + J_f*J_f*f`; the Hessian terms come from the motor's three bilinear state products. Signed interval Jacobians preserve more cancellation than the old scalar Lipschitz remainder. All companion calculations remain exact rational, with the same outward rounding between substeps.

A tube crossing a piecewise-friction corner uses the existing first-order Lipschitz endpoint formula because the smooth third-derivative argument does not apply across that corner. The whole-interval tube inclusion test, subdivision budgets, current threshold, numerical discrepancy allowance, epsilon defaults, replacement selector, 1-ms plant interval, training reward and optimizer settings are retained. This update changes the certificate producer, not the source motor specification. It does not implement a correlated Taylor-model representation or a new uncertainty-driven refinement policy.

The previously rejected representative -20 V braking candidate now passes at 1 ms with score about 0.2213. Three targeted checks cover a closed-form RL solution, an independent numerical braking endpoint comparison, and friction-corner branch rejection; 24 runtime regressions and five interval integration checks passed. Two older search regressions explicitly force the first-order fallback to preserve their original uncertified-seed scenario: second-order bounds now accept those old holding seeds. These checks do not constitute a universal implementation proof. The new training/evaluation run skips nuXmv as requested, and previous verification results must not be represented as verification of this changed certificate producer. Its output directory is `outputs/pmsm-second-order-passthrough-20261015` in the GPU workspace.

Second-order trial result: the requested 3000-step pass-through training and evaluation were attempted on CUDA. They stopped with `SHIELD_BLOCKED` after 85 and 26 steps respectively, with zero executed safety violations. The remaining blockage involves first-order enclosures across piecewise-friction corners near zero speed. No full three-second accuracy result was obtained. Local results: `../../../../outputs/pmsm-second-order-passthrough-20261015/REPORT.md` and `summary.json`. No nuXmv check was run for this trial.

## Piecewise-friction checker update, 15 October 2026

The user authorized documenting and implementing a fix for slope changes in the source friction formula. Extension C in `../../../../outputs/PMSM_local_Lipschitz_shield_design.tex` and its PDF was written before implementation. Smooth tubes retain the second-order Taylor endpoint and bounded third derivative. Boundary-crossing tubes are intersected with the three exact friction regions; signed interval bounds on `J_m(B_m)*f_m(B_m)` are combined, and the integral Taylor identity gives `X + h*f(X) + h²*C/2`. This covers uncertain crossing times without assuming a smooth third derivative at a formula boundary. It replaces the former global-norm first-order fallback and does not alter source friction, the 1-ms control period, motor parameters, safety threshold, discrepancy formula, selector, reward, or learner. No Flow* dependency or full event-isolation engine is introduced.

The two recorded blocked-state holding candidates now certify with scores approximately 0.98524 and 0.89216; live-plant snapshots remain unchanged during these checks. New tests contain both positive and negative analytic friction-boundary crossings and both blockage regressions. All 24 runtime regressions pass; the historical uncertified-seed selector tests use a test-only reproduction of the former valid conservative endpoint producer to retain their intended difficult search scenarios. These checks do not establish universal source/refinement correctness. A pass-through shielded training/evaluation trial is recorded under `outputs/pmsm-piecewise-passthrough-20261015` on the GPU server, with nuXmv skipped as requested.

Piecewise trial result: training and evaluation both completed 3000 actual plant steps / 3 seconds, with zero unresolved enclosures, shield blockages, or executed current violations. Evaluation MAE was 1279.70 RPM, essentially equal to the 1279.61-RPM zero-speed baseline on the same reference; tracking is not established by this result. Total wall time was 623.01 s. Detailed local record: `../../../../outputs/pmsm-piecewise-passthrough-20261015/REPORT.md` and `summary.json`. The changed checker was not checked with nuXmv in this trial.
